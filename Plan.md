# 🗺️ Examination Terminal: план до рабочей версии

**Цель:** задеплоенная система экзаменов с двумя демо-аккаунтами (студент и преподаватель), на которой можно пройти полный цикл: преподаватель создаёт тест → студент проходит → преподаватель видит результат.

**Где мы сейчас:** фронт и бэк уже связаны, и сценарий студента работает. Это главное отличие от Krist: здесь нужно не связывать, а **закрыть дыры** и **достроить вторую роль**.

## Этап 1. Честная проверка (2 вечера)

**Самое важное.** Пока это не исправлено, у системы экзаменов нет смысла: сейчас студент получает 100% за любой тест.

### Бэк
- [ ] Студенту не отдаются `correct_answer`, пока попытка не завершена
- [ ] `completion-test` принимает `[{ result_id, student_answer }]` и сверяет ответы с БД
- [ ] Проверка таймера на сервере: `now <= attempt_date + timelimit`
- [ ] `IntEnum` для статусов попытки
- [ ] Тесты: попытка подменить ответ, завершение после таймера, повторное завершение

### Фронт
- [ ] Отправлять только `resultId` + `studentAnswer`
- [ ] Убрать `correctAnswer` из модели незавершённой попытки

### Бонус: автосохранение ответов
В требованиях курсовой написано «фиксирует ответы в режиме реального времени», а сейчас всё отправляется одним запросом в конце. Если закрыть вкладку, ответы пропадут.
- [ ] Бэк: `PATCH /test-progress/{id}/answer { result_id, student_answer }`
- [ ] Фронт: сохранять при выборе варианта (с дебаунсом), при перезагрузке восстанавливать выбранные ответы

**Готово, когда:** тест из `tests/` с подменой `correct_answer` получает 0 баллов, а через 10 минут после таймера ответы не принимаются.

## Этап 4. Кабинет преподавателя (4–6 вечеров)

Самый большой этап и самый ценный для портфолио: появляется вторая роль со своим UI. API для большей части уже есть.

### Курсы
- [ ] Список своих курсов, создание, редактирование и удаление (`/course`)
- [ ] Страница курса: студенты (добавить по email, удалить), тесты курса
- [ ] Бэк: поиск студентов по email для добавления (`GET /profile?search=`)

### Конструктор тестов
- [ ] Создание теста: название, лимит времени
- [ ] Добавление вопросов: текст, варианты (динамический список полей), выбор правильного — радиокнопкой, без ручного ввода текста ответа
- [ ] Редактирование и удаление вопросов (`PATCH /questions/{id}` уже есть, `DELETE` добавить)
- [ ] Бэк: валидация `correct_answer in options`

### Открытие доступа
- [ ] Модалка: выбор курса и дедлайна (date-time picker Vuetify)
- [ ] Бэк: не создавать дубли попыток, один `commit` на всех студентов

### Результаты
- [ ] Таблица по тесту: студент, статус, балл, время прохождения
- [ ] Детали попытки студента
- [ ] Сводка: средний балл, сколько сдали и не сдали (ECharts уже подключён)
- [ ] **Выгрузка в CSV или Excel**, это требование из курсовой. Бэк: `GET /tests/{id}/results/export` с `StreamingResponse`

**Готово, когда:** преподаватель с нуля создаёт тест из 5 вопросов, открывает его курсу, а после прохождения студентом видит результат в таблице и скачивает CSV.
